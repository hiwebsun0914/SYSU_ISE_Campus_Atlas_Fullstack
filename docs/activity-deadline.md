# 活动截止与延后审核

本次活动于北京时间 **2026-09-17 00:00:00** 截止，后端配置为 `2026-09-17T00:00:00+08:00`。服务器时间达到该时刻即关闭操作，不需要定时任务或到点重启服务。

## 参与者规则

- 零点起停止新打卡、作品上传和投稿、投票及取消投票、新申诉；已驳回记录不能再补传或申诉。
- 以服务器接受最终提交的时间为准。截止前开始上传但零点后才最终提交的记录无效；取得上传地址不代表提交成功。
- 截止前接受的打卡、作品与申诉继续审核。打卡审核通过后照常发放地点积分和符合条件的路线奖励，重复审核不重复计分。
- 历史记录、审核状态和管理员审核继续可用。作品删除沿用既有截止限制。
- 排名沿用现有计分和审核规则；有待审记录时，零点后的积分与排名仍可能变化。

## 前后端约定

截止配置来源是后端 `data/awards.js`。公开接口 `GET /api/submissions/meta` 返回 `deadline`、毫秒时间戳 `serverNow` 和布尔值 `closed`，使用 `Cache-Control: no-store`。

截止拒绝使用业务码 `code: 4` 和 `errorCode: "ACTIVITY_CLOSED"`。新增打卡及上传限制返回 HTTP 403；已有作品业务接口保留 HTTP 200 + 业务码的兼容形式。客户端应识别业务码，不能只依赖 HTTP 状态。

Web H5 根据服务器时间校准响应式截止状态，页面持续打开、返回前台和执行写操作时都会重新判断；最终权限由服务器校验。管理员、头像和未来卡片等非活动接口不套用活动截止限制。

## 发布与验收

先测试截止边界和延后审核，再备份云端配置、数据及当前代码。后端先发布，使用现有 PM2 `app` 进程加载改动并保存进程列表；Web H5 使用 `VITE_API_BASE=/api` 构建和发布，保留上一版静态资源以兼容已打开的页面。

线上读取 `/api/submissions/meta` 核对截止时间和服务器时间。截止前 `closed` 为 `false`，零点后为 `true`；新操作被拒绝，而截止前待审记录仍可处理。边界测试使用隔离的临时数据与时钟，不修改生产时间或真实用户记录。

截止前已签发的 COS 地址在短暂有效期内可能仍可写入图片；后端最终提交校验保证其不能生成截止后的有效记录。回滚时保留当前业务数据，只恢复发布前代码与前端产物。
